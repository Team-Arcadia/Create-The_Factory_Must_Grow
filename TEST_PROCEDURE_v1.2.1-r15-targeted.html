▸ Scope of this test pass ▸ Périmètre de cette passe

Root cause of the persistent +40 leak (finally found): the player inserts an unfinished_resistor, the generic winding recipe runs for processing_time = 50 ticks (50 spool drains), and on completion the slot is replaced with a finished resistor whose RESISTANCE is fixed at 10 by the recipe JSON. The very next tick, the dedicated resistor branch takes over — RESISTANCE 10 < target so it drains the spool another (target − 10) times until RESISTANCE reaches target. For a 5% target: 50 generic + 40 resistor-branch climbing 10 → 50 = 90 total spool drains.

Fix: when the generic branch completes and the result is a resistor / coil, stamp its RESISTANCE / COIL_TURNS with the current turnPercentage.getValue() * 10 target. The dedicated branch then sees value >= target on the very next tick and exits without any further drain. Spool consumed = exactly processing_time ticks (50 right now).

Important note: with this fix, processing_time stays at 50 regardless of target. So 5% target uses 50 spool to produce a 50 ohm resistor; 100% target also uses 50 spool to produce a 1000 ohm resistor. That's a side effect of how the recipe is shaped — if it should scale, that's a balance decision for a separate pass.

Cause racine du +40 leak persistant (enfin trouvée) : le joueur insère un unfinished_resistor, le recipe winding generic tourne pour processing_time = 50 ticks (50 drains spool), à la fin le slot est remplacé par un resistor avec RESISTANCE = 10 (fixé par le recipe JSON). Le tick suivant, la branche resistor dédiée prend le relais — RESISTANCE 10 < target donc elle draine la spool (target − 10) fois de plus jusqu'à RESISTANCE = target. Pour 5% target : 50 generic + 40 resistor-branch climbing 10 → 50 = 90 drains total.

Fix : quand la branche generic complète et le résultat est resistor / coil, stamper son RESISTANCE / COIL_TURNS avec le target actuel (turnPercentage.getValue() * 10). La branche dédiée voit alors valeur >= target au tick suivant et exit sans drain. Spool consommée = exactement processing_time ticks (50 actuellement).

Note importante : avec ce fix, processing_time reste à 50 peu importe le target. Donc 5% target = 50 spool pour produire un resistor 50 ohm ; 100% target = 50 spool aussi pour produire un resistor 1000 ohm. C'est un effet de bord de la forme du recipe — si ça doit scaler, c'est une décision de balance pour une passe séparée.
