▸ Scope of this test pass ▸ Périmètre de cette passe

Neymor16's e4b80182 retest clarified the actual expectation: spool drain should scale 1:1 with the scroll-value target. The e4b80182 fix stamped the target onto the result but left the generic branch running for recipe.getProcessingDuration() ticks (50 for resistor, 100 for coil), so spool consumption did not scale — 5% target and 100% target both drained the same fixed amount.

Commit a66abd58 peeks the recipe's first rollable result template (without consuming randomness) and substitutes the duration with the live target when the output is a resistor / coil. Non-resistor / non-coil recipes keep their JSON processing_time.

New contract — 1 spool unit = 1 ohm / 1 turn end-to-end:
