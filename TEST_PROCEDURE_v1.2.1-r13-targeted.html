▸ Scope of this test pass ▸ Périmètre de cette passe

One follow-up fix shipped in b291e878 after Neymor16's f77251be retest still showed 5% target consuming 90 spool durability and 100% target finishing under 1000 ohm. Root cause was that performRecipe ran on BOTH the server and the client because tick() had no sidedness check. The server applied the authoritative drain (50 over 50 ticks); the client applied its own visible drain (40 ticks visible to the player before the next sync overwrote it). Tester saw the client value, hence 90 instead of 50.

The fix is a single line at the very top of performRecipe: if (level == null || level.isClientSide) return;. The previous guards (top-of-method target-met early-out, copy-then-setStackInSlot, target-reached check below the recipe-null block) all remain in place — they were correct, just being undermined by the duplicate client-side ticks.

Tests below verify the symptom is gone and that nothing client-side relied on performRecipe running locally.
