▸ Scope of this test pass ▸ Périmètre de cette passe

Three follow-up fixes shipped in f77251be after Neymor16's report on 242a522b. For each fix, one PRIMARY test that verifies the user-reported symptom is gone, plus 1–3 COLLATERAL tests that catch the most likely regression each fix could have introduced.

  • VAT-DUPE — arc_furnace_steel produces coal_coke_dust in the output at 0.9 chance. getMatchingRecipe.testInventory was an 8-slot wrapper over both inputInventory and outputInventory, so once a coal_coke_dust roll landed in the output the matcher saw it as a satisfied ingredient on subsequent ticks. tickRecipe's actual consumption only walks inputInventory, so the output coal_coke_dust was never debited and another roll added more each cycle = infinite dupe. Fix restricts the matcher to the four input slots.
  • WIND-EARLY-OUT — Neymor's report showed the previous winding fix still let 5%-target resistors consume ~90 spool durability instead of 50, and 100%-target resistors finish at 960 ohm. The earlier guard was placed too late in performRecipe — after the resistor branch had already exited and ticks could still slip into the generic spool-drain branch below. The new guard runs at the very TOP of performRecipe, right after the speed check, so once a resistor / coil reaches its target value the whole tick exits before any branch can decrement the spool.
  • BFO-COLLECT-WALK — When the BFO's fuel buffer hit its 64 cap, surplus coal_coke_dust on the ground stayed there (good, that's the previous fix), but the collectItems loop had locked onto items.get(0) with a 64-iteration counter — every iteration tried the same dropped coal_coke_dust and short-circuited, so other ItemEntities behind it (e.g. quartz dropped after) were never considered. Now we iterate every ItemEntity in the collection zone with an inner loop per entity that breaks on full-slot/full-cap and moves on; total budget of 64 unit-pickups per tick preserved.
