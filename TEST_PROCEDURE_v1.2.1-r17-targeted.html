▸ Scope of this test pass ▸ Périmètre de cette passe

After a66abd58 was validated 12/12 by Neymor16, one display bug remained: when an unfinished_resistor, unfinished_electromagnetic_coil or laminated_magnetic_alloy_block was being wound, the goggle progress counter and the spool durability bar stayed frozen until the recipe finished — they jumped from 0/X to X/X in one frame. Already-finished resistor / electromagnetic coil / copper coil block inputs were fine (they take the dedicated branch which already syncs per tick).

Two root causes in the generic branch:

  • Missing setChanged() / sendData() after the per-tick drain — the client never received the live SPOOL_AMOUNT / amountWinded updates.
  • The goggle tooltip displayed amountWinded / recipe.getProcessingDuration() (always 50 or 100), but the actual contract since a66abd58 is amountWinded / target (up to 1000). Denominator was lying.

Commit ea0fc0ad adds the missing sync at the per-tick drain site AND extracts the scaled-duration logic into a shared currentRequiredDuration() helper used by both performRecipe and addToGoggleTooltip, so the displayed denominator always matches the real one.
