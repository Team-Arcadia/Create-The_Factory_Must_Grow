▸ Scope of this test pass ▸ Périmètre de cette passe

Three independent fixes shipped together in f94fbeef. Tests are grouped per fix: a primary test that validates the fix and 1–2 collateral tests that catch the most likely regression each fix could have caused.

  • VAT-DRAIN — vat tickRecipe drained ingredients via the public capability, but commit 9c3d43c9 had added forbidExtraction() on the input tank to stop external pipes from siphoning. The wrapper also blocked the recipe's own drain → ingredients never consumed but output still produced. Now the drain walks TankSegments directly via the existing accessor, bypassing the public wrapper.
  • WIND-NBT — winding machine mutated inventory.getItem(0) in place via stack.set(component, value); SmartInventory never marked the slot dirty, so the slot's serialised form lagged the in-memory ItemStack. Pulling out 10 resistors at the same target gave 50/49/45/44/40 instead of all 50. Now copy → set → setStackInSlot, then setChanged + sendData.
  • BFO-CAP — blast furnace output never invalidated its IFluidHandler capability. Mekanism pipes / Create pumps held a stale handler reference (after chunk reload, etc.) and silently failed to extract until something forced a refresh. Now onFluidChanged and read both call level.invalidateCapabilities.
