✓ FIXED since r8 — From the latest playtest reports:

  • TOOLS-ENCH (e0f6c4f9) Steel/aluminum/lead toolsets and the lithium blade had no #minecraft:enchantable/* tags and no tool-group tags. The enchanting table only offered universal-tag enchants like 'reactive'. Now every tool is tagged per type (sword, pickaxe, axe, shovel, hoe) and gets the matching sharp_weapon/weapon/fire_aspect/mining/durability/vanishing enchantability. Sharpness/Smite/Fire Aspect/Looting/Sweeping Edge/Efficiency/Fortune/Silk Touch/Unbreaking/Mending/Curse of Vanishing all show up again. Test ITM-ENCH.
  • TOOLS-TIER (e0f6c4f9) Every TFMGTier returned INCORRECT_FOR_WOODEN_TOOL — steel/aluminum tools could mine ore visually but at wooden harvest level, dropping iron tier loot but at stone-tool speed. Now keyed per material: steel = INCORRECT_FOR_DIAMOND_TOOL, aluminum = INCORRECT_FOR_IRON_TOOL, lead = INCORRECT_FOR_STONE_TOOL. Test ITM-MINE.
  • VOLT-SOURCE (bb7b0a00) Accumulator + Converter no longer extend VoltageAlteringBlockEntity (fixes the StackOverflow on accumulator chains), but they were also no longer recognised as voltage sources by neighbour cables. New IVoltageSource marker interface — IElectric.voltageGeneration / powerGeneration recognise it in addition to VoltageAlteringBlockEntity, with a guard to avoid double-counting. Converter pushes FE→V again, accumulators discharge into TFMG cables. Tests ALT-04 and STO-03 retest.
  • VAT-CASCADE (4fef83dd) Vat output fluids now cascade across multiple output segments instead of stalling on the first segment that can't fit a 144 mB or 288 mB output. The fireproof vat showed 64 of every ingredient and 3 graphite electrodes operational but no recipe progressed because the molten_steel/molten_slag output tanks had partial fills nowhere big enough for a single cycle. Test MAC-VAT-CASCADE.
  • VAT-INPUT-EXTRACT (9c3d43c9) Vat input tank gained forbidExtraction — Mekanism mechanical pipes in pull mode no longer drain the ingredients out of the input. Test MAC-VAT-PIPE.
  • VAT-PREFLIGHT (9c3d43c9) Vat now simulates placing every recipe output before consuming any input. The user reported a mixer that 'accepts every ingredient but produces nothing' on a recipe whose output tank was full of a different fluid — drained ingredients went nowhere. Pre-flight gates the consumption.
  • VAT-BITUMEN (9c3d43c9) New vat mixing recipe: 250 mB water + 1 asphalt_mixture → 1000 mB liquid_asphalt (cast iron / steel / firebrick vats). Test MAC-VAT-BITUMEN.
  • VAT-FREEZE-COMP (01168512) Freezer + Compactor wired as IVatMachine. New recipes: cooling_fluid (freezer), compressed_lpg (compressor at pressure>=1), liquid_air (both). Test MAC-FRZ-01 / MAC-CMP-01.
  • BASIN-CAP (0c16847c, 957bfab5) Casting basin tank lifted from 144 mB to 1000 mB, recipe gate switched from 'tank exactly full' to 'tank has enough'. Render bounds clamped to the actual basin cavity (Y 1/16..8/16) so a full basin no longer spills 2 blocks of fluid through its own model. Test OIL-CAST.
  • VAT-RENDER (81f8a0f5) Vat fluid render distributes the visible column across populated segments instead of stacking N times the visible volume. Multi-fluid vats no longer flicker through their ceiling.
  • STATOR-VISUAL (8358c374) Large generator stators now snap to their correct STATOR_STATE/FACING/VALUE as each is placed, instead of waiting for the full 8-stator ring to be complete. Power generation still gates on the complete ring. Test GEN-04.
  • RECIPES (d23a142b) Arcadia V2 KubeJS workarounds integrated natively: hardened planks now key on c:stripped_logs (any modded stripped log works), steel mechanism trimmed to 4 deploy steps with steel/aluminum/screw/screwdriver and 0.8/0.2 results.

⚠ STILL KNOWN — carried over:

  • ALT-01 Wrong-direction placement still requires break + replace.

Désormais par matériau : steel = INCORRECT_FOR_DIAMOND_TOOL, aluminum = INCORRECT_FOR_IRON_TOOL, lead = INCORRECT_FOR_STONE_TOOL. Test ITM-MINE.

Le vat firebrick montrait 64 de chaque ingrédient + 3 graphite electrodes mais ne produisait rien parce que les segments molten_steel/slag avaient des fills partiels insuffisants pour un cycle complet. Test MAC-VAT-CASCADE.
  • VAT-INPUT-EXTRACT (9c3d43c9) Le tank d'input du vat a maintenant forbidExtraction — les pipes mecaniques Mekanism en mode pull ne drainent plus les ingrédients du tank d'input. Test MAC-VAT-PIPE.
  • VAT-PREFLIGHT (9c3d43c9) Le vat simule maintenant le placement de chaque output avant de consommer les inputs. Le user a reporté un mixer qui 'accepte tout mais ne produit rien' sur une recette dont l'output tank était plein d'un autre fluide — les ingrédients drainés disparaissaient. Le pre-flight gate la consommation.
  • VAT-BITUMEN (9c3d43c9) Nouvelle recette mixing : 250 mB water + 1 asphalt_mixture → 1000 mB liquid_asphalt. Test MAC-VAT-BITUMEN.
  • VAT-FREEZE-COMP (01168512) Freezer + Compactor branchés en IVatMachine. Nouvelles recettes : cooling_fluid (freezer), compressed_lpg (compressor pressure>=1), liquid_air (les deux). Tests MAC-FRZ-01 / MAC-CMP-01.
  • BASIN-CAP (0c16847c, 957bfab5) Capacité du tank du casting basin passée de 144 mB à 1000 mB, le gate de la recette passe de 'tank exactement plein' à 'tank avec assez de fluide'. Le rendu fluide est clampé à la cavité réelle du basin (Y 1/16..8/16) pour qu'un basin plein ne fasse plus déborder 2 blocs de fluide à travers son propre modèle. Test OIL-CAST.
  • VAT-RENDER (81f8a0f5) Le rendu fluide du vat distribue la colonne visible entre les segments populés au lieu de cumuler N fois le volume. Les vats multi-fluides ne clignotent plus à travers leur plafond.
  • STATOR-VISUAL (8358c374) Les stators du large generator s'orientent correctement dès qu'on les pose, au lieu d'attendre que l'anneau de 8 soit complet. La génération électrique reste gatée sur l'anneau complet. Test GEN-04.
  • RECIPES (d23a142b) Workarounds Arcadia V2 KubeJS intégrés nativement : hardened planks utilise désormais c:stripped_logs (tout stripped log moddé fonctionne), steel mechanism raccourci à 4 deploy steps avec steel/aluminum/screw/screwdriver et résultats 0.8/0.2.
